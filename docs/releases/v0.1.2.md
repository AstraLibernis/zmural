Windows fixes from a full audit of zmural, with one change to zip imports on both systems. Linux is otherwise as in 0.1.1, apart from the move to Zig 0.17.

**This is still an early pre-release.** Download and install exactly as for [0.1.1](https://github.com/AstraLibernis/zmural/releases/tag/v0.1.1): quit zmural, unpack the new version next to the old folder, start zmural from the new folder.

## Fixed (Windows)

- **A video file cut short while it played** (a download still running, a sync tool rewriting it) left the player spinning on about three CPU cores for good. zmural now notices within a second that the file changed, says which file is broken, and shows the wallpaper it had before.
- **Uninstall with a custom settings folder** (`ZMURAL_CONFIG_DIR`) deleted that whole folder. It now removes only zmural's own files there.
- **zmural could stop answering `zmural-console`** for good after one failed attempt to listen. It keeps trying now.
- **After an Explorer restart** the wallpaper could land above the desktop icons. zmural waits for the icons first.
- **At logoff** the settings are saved before anything else, so a slow shutdown can't lose them.
- **Without a desktop** (Explorer gone) zmural retried every half second for ever and logged each try. It backs off to every 10 seconds and logs once.
- Smaller ones: the tray menu does nothing after a logoff that ran while it was open; a network video still loading isn't restarted as stuck; two rare leaks when a video fails to load or the settings window closes during an import.

## Lighter on the PC (Windows)

- Wallpaper players run at below-normal CPU and GPU priority, so a game or a build goes first.
- Videos decoded on the CPU use two threads, and no audio is decoded while the wallpaper is muted (the default): about half the threads and half the memory of before for such a video.
- While a fullscreen app pauses every monitor, zmural is no longer woken by every mouse move.

## Safer imports (Windows and Linux)

- **Shortcut-type files are left out of every import:** `.lnk`, `.url`, `.scf`, `.pif`, `.library-ms`, `.search-ms`, `.searchConnector-ms` and `desktop.ini`. Merely opening a folder that holds one can make Windows Explorer sign in to a remote server with your login. The import says how many it left out; everything else in the zip is unpacked as before.
- On Windows, imported files get the "downloaded from the internet" mark before they appear in the library, not just after.

## Inside

- The Windows release ships a newer libmpv (mpv-winbuild `2026-11-20-ee54be6e1d`). Its credits file now also lists libssh and OpenAL Soft, which were inside the earlier build too but were missing from the list.
- Built with Zig 0.17.1.

## Tested

The fixes were tested on Windows 11: the automated tests natively, and by hand on a real desktop a video cut short while playing (with GPU decoding), an Explorer restart, a fresh install and an import of a zip holding shortcut files. A logoff was only simulated. Not tested on a desktop this time: Linux, which has not run on one since the move to Zig 0.17 (it builds and its automated tests pass).

## Known limitations

As in 0.1.1: not code-signed (SmartScreen may warn), no updater, multiple monitors tested only on virtual screens, no screen-reader support in the settings window, video and picture renderers not yet sandboxed. New on the list: on Windows the settings window's thumbnails are made inside zmural itself. Found by the audit and not fixed yet: on Linux, a wallpaper can fail to come back after a very short fullscreen flicker; a zip that lies about its own sizes can pass the unpack-ratio check (the 4 GiB limit still holds). See the README's [Security](https://github.com/AstraLibernis/zmural#security) section.

## Reporting a crash

After a crash zmural shows a line like `zmural 0.1.2 windows crash: 1216a76 10fab48`. Please include that line and your `zmural.log` (Windows `%LOCALAPPDATA%\zmural\zmural.log`, Linux `~/.local/state/zmural/zmural.log`) in an issue.

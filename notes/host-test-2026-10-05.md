# Host test as a new user: 2026-10-05

Run from a host shell on the owner's desktop (Fedora 44, Plasma 6.7.5 Wayland, Qt 6.11.2,
RX 9070 XT, one 2560x1440 monitor). The old install (e0815f5) was removed with its own
`zmural-console uninstall --yes` and its folder deleted; the release tarball of 047d40e
(built from a clean worktree, plugins from the Debian 13 root) was extracted to
`~/.local/opt/zmural` and started with no settings, as the README says. No mouse or
keyboard input was possible (KWin has no virtual-pointer protocol), so nothing in the
settings window was clicked.

## Findings (most important first)

1. **Empty zip crashes `zmural-console import`.** A zip with no entries:
   `panic: start index 1 is larger than end index 0` in `import.run`, exit 134, core dumped.
   (`python3 -c "import zipfile;zipfile.ZipFile('e.zip','w').close()"`.) Open file in the
   settings window runs the same program.
2. **First run shows a black desktop.** With 9 videos already in `~/Videos/Wallpapers`, the
   first start sets Plasma to the zmural plugin, notifies "Your desktop now shows zmural's
   wallpaper", and shows nothing: `wallpaper : (none)`, log `no wallpaper set: use --apply
   <path>`. The user's own picture is gone and nothing says to pick one. No settings.toml is
   written until the first change.
3. **A file that can't be played is accepted and kept.** `apply /etc/passwd` and `apply` of a
   text file named `.mp4`: exit 0, saved as `wallpaper =` in settings.toml, shown by `status`
   as the wallpaper, the desktop goes black, no notification. Only the log says `cannot play
   ...: unrecognized file format`. The previous wallpaper is not kept.
4. **Quit leaves a black desktop.** After `zmural-console quit` the Plasma plugin stays
   selected with nothing to show (mean colour 0,0,0). Uninstall does put Plasma's own picture
   back. README says nothing about this.
5. **Thumbnails: 8 of 9 videos show the placeholder** in the settings window on a fresh
   install (only one had a picture).
6. **Lively web package on Linux:** imported (folder + converted zmural.toml, `type = "web"`)
   and then `zmural didn't show it: not a usable wallpaper package (zmural's log says why)`,
   but the log has no line about it. The unusable folder stays in the library.
7. **Import unpacks any file type.** A zip holding `run.sh` and a PNG imports both (mode 644,
   not executable). Probably fine; noted in case only media was meant.
8. **Leftovers:** after quit, `/run/user/1000/zmural/kwin-foreground.js`; after uninstall,
   `/run/user/1000/zmural-icons-1000.ttf` (both on tmpfs, gone at logout).
9. **Small things:** tray tooltip names a package by its folder (`lively7`), not its title
   (`Test Lively Clip`); the player card says "Nothing showing" over "Playing, muted";
   before the first wallpaper, `status` lists the monitor as `qml-display` and the log says
   1920x1080 (right name and size once a wallpaper shows); importing the same zip twice
   makes `pics (2)` without a word.

## Passed

- Uninstall of the old version and of this one: every trace gone except the items in 8;
  the closing hint now names the install folder; declining at the prompt removes nothing.
- First run: plugin built on Qt 6.8 loads on Qt 6.11.2, desktops switched, tray icon, launcher,
  start at login; two notifications (plugin, start at login), none from the requirements check.
- Settings window: opened and closed 3 times (`--settings`, tray menu, tray click), no crash,
  no zombie, fully drawn at 1.5 s.
- Video: zero-copy 2560x1440, `decoding h264 on the GPU (vaapi)`, renderer 1.8 % of a core,
  0 % paused; daemon 0 %, 22 MiB.
- PNG, GIF; fill crop and center measured from screenshots; pause/play, mute/unmute,
  next/previous, order, rotate, rescan, props/prop/--reset; live reload of settings.toml.
- Automatic pauses, each shown in `status` with its reason: fullscreen, maximized,
  game_mode, session_locked, power_saver, app_rule.
- Tray menu over dbusmenu: Paused, Next, Settings; Activate opens the window.
- Watchdog: kill -9 restarts in 2 s without a notice; two SIGSEGVs give one notification,
  "not told again" for the second, the `crash :` line in `status`, crash lines in local time
  with code addresses; backoff 4 s then 8 s.
- Zips: export of a video and of a package folder, import to `--to` and to the library,
  `--apply`; refused with a clear line and exit 1: `../` names, absolute names, a link, a file
  that isn't a zip. Lively video package converts and plays.
- Non-UTF-8 file name: applied, tray stays on the bus, tooltip shows U+FFFD.
- 40 wallpaper changes: 40 first frames, no error or warning, fds 18 -> 18, RSS unchanged,
  no zombie; 15 changes with no delay: one renderer left, no error.
- Second instance exits saying zmural is running; quit takes 0.05 s and the renderer with it.
- Started by `app-zmural@autostart.service` (the unit a login uses): same wallpaper comes back.

## Not tested

Anything needing clicks or keys in the settings window (Open file importing a zip, Uninstall
button, Escape, arrows); the switch flash (no fast capture from a shell); session inactive
(VT switch), a real re-login, sound through the speakers; suspend (masked on this machine),
two monitors, battery, remote session, GNOME, other Plasma versions.

## Resolved the same evening (from the host session; NOT committed)

Owner's decisions: the black desktop on first run and after quit stays (2, 4); import
unpacks whatever the zip holds, the user's business (7); copies keep the `(2)`, `(3)`
numbering (9).

- 1 fixed: `check` returned `error.Empty` only after the overlap loop, which slices
  `spans[1..]`; the check now comes first. Test case added (a zip with no entries).
- 3 fixed as a notice, both OSes: a renderer's "cannot play/show" now also notifies
  ("zmural can't show this wallpaper", the reason, "Pick another wallpaper"), once per
  wallpaper in a row (`tellCantShow`). The file is still accepted and saved. Windows side
  only compiled.
- 5 not a bug: Linux reads the desktop's thumbnail cache and makes none itself; only one
  of the nine videos was in `~/.cache/thumbnails`. Making its own would be a feature.
- 6 withdrawn: the log does say why (`type = "web" doesn't match its entry`), and the test
  zip was wrong (a Lively web type naming an mp4).
- 8 fixed: the KWin script file is deleted once KWin has run it (app rule re-checked on
  the host); uninstall removes the icon font from the runtime folder (not re-run on the host).
- 9: the player card says "Click a wallpaper to show it" and the tray tooltip just
  "Nothing showing" when nothing shows. The tray naming a package by its folder is
  `displayName`'s documented behaviour, left.

Checked: unit tests 206/213 (7 skipped), `zig build`, Windows cross-build, import (25),
packages (12), uninstall (7) rigs; on the host with the new tarball: empty zip refused
("it is empty", exit 1), one notice per unplayable file, app rule.

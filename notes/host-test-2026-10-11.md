# Host test as a new user: 2026-10-11 (main 9797d58, beta-readiness pass)

Run from a host shell on the owner's desktop (Fedora 44, Plasma 6.7.5 Wayland, Qt 6.11.2,
RX 9070 XT, one 2560x1440 monitor, scale 1). The 16b8bcb install was removed with its own
`zmural-console uninstall --yes` (zero leftovers, hint now says "still pictures and
thumbnails") and its folder deleted; the release tarball of 9797d58 (clean worktree,
plugins from the Debian 13 root, sha256 4e89f50f…) was extracted to `~/.local/opt/zmural`
and started with no settings. Input by the uinput absolute mouse + keyboard from 10-06
(rewritten, 60 lines),
geometry and window closing by KWin scripts, screenshots by `spectacle -b -n -f`.
Memory: valgrind memcheck over every `zmural-console` command, and RSS/fd/thread soaks of
the daemon (30 wallpaper changes, 45 settings-window open/close cycles). At the end the
owner's settings were restored and zmural reinstalled from the same tarball.

## Findings (most important first)

1. **The settings window's Uninstall does nothing when zmural runs in a unit that dies
   with its main process.** The window spawns `zmural --uninstall --from-window` as a
   child of the daemon (`platform_linux.zig:958`); the uninstaller's first step asks the
   daemon to quit. Under a unit with `ExitType=main` + `KillMode=control-group` (what
   `systemd-run --user` makes, and what any hand-written user service has by default),
   systemd kills the whole cgroup the moment the daemon exits, so the uninstaller dies
   before removing anything: the window closes, zmural stops, **every file stays** (config,
   plugin, autostart, launcher, log), Plasma keeps `org.zmural.kde`, and the user believes
   it is gone. 1 of 1 under `systemd-run`; 0 of 1 under `app-zmural@autostart.service`
   (Plasma's generated unit has `ExitType=cgroup`, so the child lives on and everything
   was removed). A terminal start is safe too. Fix: don't rely on a child outliving the
   daemon: let the daemon run `uninstall.run` itself on its way out when the window asked
   (a flag checked after `shutdown`), or at least make the uninstaller do its removals
   *before* it asks the daemon to quit, and quit last. `zmural-console uninstall` from a
   terminal is unaffected (it is the terminal's cgroup).
2. **The "Remove zmural from this computer?" dialog truncates its text.** The body is one
   line ending in an ellipsis: "It stops, and its settings, menu entry, start at login and
   …"; the second sentence ("Your wallpapers and their folders stay.") never shows. 2 of 2.
   The Reset dialog likely shares the code path (not checked). Fix: wrap the body (the
   dialog is 440 px wide; two or three lines fit).
3. **Nit (valgrind):** `zmural-console apply /nonexistent` exits with the control socket
   still open (`sdk.control_client_linux.Client.connect`): the error path returns without
   closing. Harmless at exit. Every other command (version, status, props, autostart
   status, apply, next, previous, rotate off, an unknown command) ran under memcheck with
   **0 errors, 0 definite leaks, fds balanced**.
4. **Carried from 10-10 (unwritten then):** a fresh start creates an empty
   `~/.config/zmural/` before anything is saved; after a quit with nothing changed the empty
   folder stays (settings.toml rightly does not). Cosmetic; uninstall removes it.
5. **Carried from 10-10:** README has no "updating" section. Extracting a new tarball over
   the old folder works (10-10: plugin self-upgrade fired, no re-login) but nothing says so.
6. `zmural-console apply --monitor 1 <path>` fails with `MissingArgument`; only
   `apply <path> --monitor 1` works. The help text shows the working order, so documented,
   but the error could say "the path comes first", or options could be accepted anywhere.
7. **Worth knowing, not a bug:** a fill-mode change (`fill fit`, `fill default --monitor 1`,
   `follow --monitor 1`) starts a **new renderer** and the old one exits ~80 ms later, so up
   to three renderer processes exist for a moment; it is always back to one afterwards.
   If fill was meant to be a live property, this is where it isn't.

## Harness notes (host, Plasma)

- Transient units for the daemon: `systemd-run --user --unit X` gives `ExitType=main`,
  which is what exposed finding 1. To mimic Plasma's login unit add
  `-p ExitType=cgroup`. The real login unit `app-zmural@autostart.service` disappears from
  systemd the moment the autostart entry is removed (it is generated from it), so after an
  uninstall the reinstall runs as a transient unit until the next login.
- `absmouse.py W H move:X,Y|click|rclick|key:ESC|wait:MS…` (sudo, /dev/uinput): an
  absolute mouse + a keyboard; 1:1 screen pixels on KWin, 1 s settle after creation.
  Window origin from a KWin script reporting `clientGeometry` over `callDBus` to
  `org.zmural.probe` + `dbus-monitor` (`kwinrun.sh`). KWin places the window differently
  each open, so probe before every click sequence.
- The General page's rows shift by ~70 px when the Troubleshooting crash row is present:
  take the screenshot first, then compute button coordinates.
- `spectacle -b -n -f -o` (full screen) and crop with PIL; `-a` grabs whatever window is
  active, which may not be zmural's.
- `pkill -f` matches the calling compound command, so it can kill the shell running it.
  Use `pkill -x`/`pgrep -P`.
- The two-address crash line decodes with `zig build crashcode -- "<line>"` in the release
  worktree.

## Fixed (2026-10-12)

1. **Uninstall from the window** no longer starts a child: the window marks it
   (`app.uninstall_on_exit`), asks zmural to quit, and zmural runs `uninstall.run` itself
   after its shutdown, in its own process (`daemon/main.zig`, `already_stopped`). Windows
   is unchanged (its uninstaller is not in the renderers' job). `tools/uninstall-test.sh`
   part 3 runs zmural as a session leader, kills the whole session the moment zmural
   exits (as systemd kills the cgroup), and holds the removal back 1.5 s
   (`ZMURAL_TEST_SLOW_UNINSTALL`, standing in for Plasma's D-Bus round trips). The old
   code fails it (`.config/autostart/zmural.desktop` still there); the new one passes.
   Found on the way: `uninstall.zig`'s `sleepMs` gave nanosleep a nsec of a second or
   more for waits ≥ 1000 ms, which the kernel refuses (it slept 0); only 100 ms had been
   used, so nothing real was affected.
2. **The confirm dialog wraps** its paragraphs at spaces and grows to fit
   (`platform_linux.zig` `questionRows`); checked by a screenshot on headless Sway: both
   sentences show. `tools/keyboard-test.sh` passes.
3. **`zmural-console`** closes its connection before exiting on a refused request
   (`report` returns false instead of exiting).
4. **Left as is:** the empty `~/.config/zmural/` is made on purpose so a hand-written
   settings.toml has a place, with a test saying so (`settings.zig`); uninstall removes it.
5. Done in the README (08e1c66): an Updating section.
6. **`apply` and `fill` take `--monitor M` before or after their argument**
   (`withMonitor`), with tests (mutation-checked).
7. Not a bug; unchanged.

Also: `tools/plugin-root.sh` keeps the Debian 13 root in `~/.cache/zmural-build/debian13`
(was `~/.cache/zmural/debian13-build`, which uninstall deletes) and moves an old one there
once.

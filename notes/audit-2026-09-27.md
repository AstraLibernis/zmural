# Blind audit #2 (2026-09-27), after the audit-1 fixes

This was run by a fresh agent that couldn't see `notes/` (so not audit #1 either). `zig build test` gave 82/82 at the time.
While it was running, the settings-window protocol work landed, and the agent re-checked those files.
It also saw one bug fixed during the run: `Conn.send` used an 8 KiB encode buffer, and it now uses a full frame.

| id | severity | verdict | location | summary |
|---|---|---|---|---|
| F1 | medium | PLAUSIBLE | runtime_windows.zig (WM_ENDSESSION → shutdown) | After a logoff shutdown the message loop keeps dispatching queued renderer/control/timer messages over freed lists. The likely result is an access violation at logoff. |
| F2 | medium | CONFIRMED | runtime_windows.zig `.window` handler | A renderer that reports HWND 0 panics the daemon (`@ptrFromInt(0)` into a non-null HWND). |
| F3 | medium | CONFIRMED | runtime run()/save() | If the startup wallpaper is briefly unavailable (a USB drive or a late mapped drive), the next save writes `wallpaper = ''` and the setting is lost. |
| F4 | medium | CONFIRMED | lifecycle.zig ended() | The "5 crashes in 60 s" window is anchored at the first crash and never slides. A renderer that crashes 25 s after each start never gives up. |
| F5 | medium | CONFIRMED | runtime openSettings/save | Hand edits made via tray "Open settings file" are overwritten by the next save or by Quit. |
| F6 | low | CONFIRMED | daemon/main.zig | `--paused` (a testing aid) is persisted, so every later session starts paused. |
| F7 | low | CONFIRMED | runtime start(): renderer pipe names | Renderer pipe names (pid, id, counter) are predictable, so another local user can squat them and the wallpaper never starts. |
| F8 | low | CONFIRMED | library.scan on the UI thread | Scanning a folder on an offline network share freezes the daemon for the SMB timeout. |
| F9 | low | CONFIRMED | runtime playable() | Any path starting with `\\` skips every check, including `\\?\` and `\\.\` device paths. |
| F10 | low | CONFIRMED | control_client / pipe.connect | The CLI and the second-instance handoff have no read timeout, and the busy-pipe wait is unbounded. |
| F11 | low | CONFIRMED | runtime onRenderer | Renderer log text is written verbatim (it can forge log lines), and a renderer can attach its window to a monitor it doesn't own. |
| F12 | low | PLAUSIBLE | pipe.zig DACL `OW` | An elevated zmurald has Administrators as the pipe owner, so the user's normal CLI is refused. |
| F13 | low | CONFIRMED (design) | process.zig / README | Renderers parse untrusted media with the user's full token (the job only limits UI access), so the README overstates the isolation. |
| F14 | low | CONFIRMED | facts.zig exeName | App rules can't match exe names that are non-ASCII or longer than 64 bytes. |
| F15 | low | CONFIRMED | get_settings / lists.zig | Lists can be longer than their reply share and are silently truncated. **Fixed with the settings window:** the limits now always fit. |
| F16 | low | CONFIRMED | runtime shutdown/run | `library_dirs`, `app_rules` and `user_dirs` are never freed, and run()'s early-error paths leak (exit-time only). |
| D1 | dead | CONFIRMED | renderer.zig / windows_renderer | `set_property`, `seek` and `screenshot` are never sent, yet the renderer implements them (writing a file anywhere, setting any mpv property). |
| D2 | dead | CONFIRMED | control.zig | `wallpaper_changed` and `playback_changed` are never pushed. If they were, the client would take them for replies. |
| D3 | dead | CONFIRMED | various | Stale docs and comments: testpattern mentions `--demo`; transport.zig says the scope is the user name and still has a TODO; router.zig's ownership comment; the main.zig help mentions M2; the README says the watchdog kills renderers; MILESTONES gives the old test count. |
| D4 | dead | CONFIRMED | various | `st.kind` is never read, `SW_HIDE` is unused, and the `loaded`/`frame_ready` messages are ignored. |

Test gaps it names:
- the F4 trace;
- the startup wallpaper surviving a missing file;
- `--paused` not being persisted;
- the handleRequest/setList/reset logic;
- the server reply size;
- router ID continuity;
- toml edge cases: `#` inside strings, arrays without commas, a tab plus a quote;
- a wire string prefix longer than the body.

## Status (2026-09-27)

Every finding is fixed, including D1–D4 (F15 was already fixed). See the "Audit #2 fixes" section in `docs/MILESTONES.md` for what changed and how each fix was checked.

# Compatibility floors: 2026-10-05

What zmural depends on, the oldest version each needs, and what that covers. From three audits
(measured on the release builds where marked, else from source or upstream docs). Nothing
here was run on an older system; a floor is a requirement, not a tested claim.

## Decided the same day (owner)

- **Windows 11 only.** Windows 10 items (#8, the Win10 rows below) are not work to do.
- **Desktop plugins: what they declare.** KDE: Plasma 6 (built on Qt 6.8 in Debian 13, as
  upstream's own release is built on an older distro). GNOME: the extension's list (48 to 50).
  No reverse-engineered support beyond that; GNOME 51 comes with an upstream update.
- **Everything else: say what's needed, don't patch.** #4, #5, #6, #7 and #9 became one
  startup check plus the host refusing clearly (MILESTONES "Requirements"). No new
  fallbacks, no X11 or Plasma 5 work.
- Done: #1 (baseline CPU), #2 (Debian 13 build), the check; README "Requirements".

## Problems found (fix list)

| # | OS | Problem | Fix |
|---|---|---|---|
| 1 | Windows | The release zip is built for the build machine's CPU (`zig build package` with no target): built on a Zen 5, it would crash on CPUs without AVX-512 | Make the Windows package step require an explicit target, as Linux's does (baseline x86-64) |
| 2 | Linux KDE | Plugin built against Qt 6.11 (this machine); needs only ~6.5 (`MultiEffect`) | Build it on Debian 13 (Qt 6.8); check Qt before installing it |
| 3 | Linux GNOME | Extension declares GNOME 48–50; GNOME 51 is out (Arch, Tumbleweed) and refused; 46/47 (Ubuntu 24.04 LTS) likely work but aren't listed | Test on 46, 47, 51 and widen the list |
| 4 | Linux | No fallback on KDE/GNOME: when the plugin/extension can't run (Plasma 5, Plasma X11, unlisted GNOME) nothing shows | Fall back to the still picture through the portal, and say why |
| 5 | Linux | Layer-shell host requires wl_output v4 (wlroots 0.16): Debian 12's Sway 1.7 gets a blank desktop, silently | Accept v3, name outputs another way |
| 6 | Linux | No dmabuf v4 or no GPU render node: background colour only, or endless renderer restarts | Exit "unsupported" so the daemon falls back to the still picture |
| 7 | Linux KDE | Plasma on X11: black desktop until `QT_XCB_GL_INTEGRATION=xcb_egl` is set by hand | Set it (systemd drop-in) or at least say so |
| 8 | Windows 10 | Settings icons use "Segoe Fluent Icons", which Windows 10 lacks: likely empty boxes | Fall back to "Segoe MDL2 Assets" |
| 9 | Linux | Budgie 10.9 (and probably GNOME Flashback) are sent to the GNOME extension path, where nothing shows | Detect them before the GNOME path |

## Windows

Honest floor: **Windows 10 1703**, x86-64 (static imports `SetProcessDpiAwarenessContext`,
`GetDpiForWindow`; libmpv needs 1607). Claim: **Windows 10 22H2 and Windows 11**. Only 25H2 has
been tried on a desktop; CI runs Server 2022/2025.

| Item | Floor | Below it / without it |
|---|---|---|
| Static imports | Win10 1703 | Won't start |
| libmpv (pinned 2026-09-26 build) | Win10 1607 | — |
| Mica backdrop | Win11 22H2 | Flat window (graceful) |
| Dark title bar (attribute 20) | Win10 2004 unofficially, Win11 | Light title bar on 1809/LTSC 2019 |
| Segoe Fluent Icons | Win11 | Win10: icons likely missing (#8) |
| Desktop layer (WorkerW) | undocumented; 24H2+ layout handled | Tested on 25H2 only |
| WebView2 runtime | 1.0.1072.54 (`ICoreWebView2_8`) | Web wallpapers only fail, with a message; LTSC/Server may lack it |
| D2D, DirectWrite, shell, tray, jobs, pipes | Vista to Win8 era | — |
| CPU | native today (#1) | — |

## Distro summary (after fixes 2–5, as a target)

Works: Debian 13, Ubuntu 25.04+, Fedora 42+, openSUSE Leap 16 and Tumbleweed, Arch, Pop!_OS 24.04,
and (with #3) Ubuntu 24.04 GNOME, (with #5) Debian 12 Sway. Never: Ubuntu 22.04 (glibc, mpv),
Plasma 5 distros (Kubuntu 24.04, Debian 12 KDE, Leap 15.6), X11-only desktops.

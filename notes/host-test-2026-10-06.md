# Host test as a new user: 2026-10-06 (main cfaf8f8)

Run from a host shell on the owner's desktop (Fedora 44, Plasma 6.7.5 Wayland, Qt 6.11.2,
RX 9070 XT, one 2560x1440 monitor, scale 1). The 17acc6d install was removed with its own
`zmural-console uninstall --yes` (zero leftovers) and its folder deleted; the release tarball
of cfaf8f8 (built from a clean worktree, plugins from the Debian 13 root, sha256 91683bb8…)
was extracted to `~/.local/opt/zmural` and started with no settings, as the README says.
First time with input: a uinput **absolute** mouse plus a uinput keyboard (a 60-line Python
script run with sudo, no project code) gave real clicks and keys on KWin, 1:1 in screen
pixels, so the Welcome page and the Wallpapers page were driven for real. Screenshots by
`spectacle -b -n`, window geometry by a KWin script reporting `clientGeometry` over a fake
D-Bus name. The owner's settings.toml was restored at the end and zmural reinstalled fresh
from the same tarball (second full uninstall, also clean).

## Findings (most important first)

Fixed the same evening, except 2 (kept as designed, owner), 5 and 6: see the last section of
`notes/stopping-point-2026-10-06.md`. Each fix has a rig check that fails
without it. None of them has been seen on this desktop yet.

1. **Fixed (9432528).** **Crash on quit when the settings window is open (KDE).** `zmural-console quit` with the
   window open ends in `CRASH: General protection exception`, core dumped, and the next start
   says "zmural stopped unexpectedly last time". 2 of 2 with the window open, 0 of 2 without.
   Decoded with `zig build crashcode` against this build:
   ```
   runtime_linux.evaluate            runtime_linux.zig:952   (for (rt.displays.items) ...)
   os.dbus.Conn.call                 dbus.zig:504            (hook dispatch while waiting)
   foreground_linux.stopKde          foreground_linux.zig:162
   runtime_linux.shutdown            runtime_linux.zig:1919
   ```
   `shutdown` frees the displays, renderers and router first, and only then calls KWin
   (`unloadScript`) over the bus. While `call` waits for that reply it dispatches whatever
   arrives to `onBusMessage`; closing the settings window makes KWin's foreground script
   report the newly focused window, that handler runs `evaluate`, and `evaluate` walks
   `rt.displays`, already deinitialised. Without the window nothing arrives in that gap.
   Fix: call `foreground.stopKde` (and clear `bus.hook`) **before** anything is torn down, or
   make `evaluate` return while shutting down. The Sway rig can't see it (no KWin script).
2. **Kept as designed (owner, 2026-10-06): Welcome and Prism until the user changes something.** **Welcome opens on every start until something is saved.** First run: Welcome opened by
   itself, as designed. Close it, `quit`, start again: `first run: opening the settings
   window` and Welcome again. `firstRun` is `Store.fresh`, settings.toml is written on the
   first change only, and Prism is filled in without a save, so a new user who is happy with
   Prism and closes the window gets Welcome at every login. Fix: save once when the first
   run's window opens (or when Prism is first filled in), so the second start is not fresh.
3. **Fixed (aadee4c), in zmural's own cache.** **Thumbnails depend on what Dolphin happened to cache** (the "why" behind 10-05's finding
   5). On Linux `makeThumb` reads only `~/.cache/thumbnails/{x-large,large,normal}/<md5 of
   the file URI>.png`. Of the 9 videos, exactly one (`waterfall-by-the-forest…`) has such a
   file (`normal/`, 128 px, with ffmpegthumbs' filmstrip frame), so that one shows and 8 are
   placeholders; nothing on this machine generates the others until Dolphin shows the folder
   with previews on. Proof: a frame from `zmural --still-frame` scaled to 256 px, saved with
   `Thumb::URI` + `Thumb::MTime` into `~/.cache/thumbnails/large/` for `autumn-river…`,
   showed on its tile at the next window open with no other change. `--still-frame` takes
   1.4 s per video here and writes a 3840x2160 PNG (10 MB; a thumbnail wants a scaled copy).
   Suggested fix: when the cache has nothing, make the frame with `--still-frame` (already a
   child process) and write a spec thumbnail into `~/.cache/thumbnails/large/` (Dolphin then
   gets it too), or into zmural's own cache. **Prism ships without a thumbnail too**: its tile
   is a placeholder on the Welcome page it is meant to sell; a `Prism.png` beside it would do.
4. **Fixed (df80a0e, 196f4d4).** **Small labels.**
   - `status` says `muted : yes (by you)` on a fresh install where the user did nothing;
     `muted` defaults to true. "by you" is the manual-flag label from `pause`.
   - The fallback notice says "Showing Prism.webm again" when nothing had ever played (the
     saved wallpaper was broken from the first start).
   - The moved-install case logs `no wallpaper set: showing zmural's own` though a wallpaper

5. **First start only: a renderer at 1920x1080, then the real one.** The KDE plugin first
   reports `qml-display … 1920x1080`, a renderer starts for it and exits 0.3 s later when
   the display says 2560x1440 (renderer 1 started/exited, renderer 2 took over). Later
   starts report the right size at once. Cosmetic.
6. **Not a bug, worth knowing**: a file dropped into a library folder is not seen until

7. **Fixed (82b0f6b).** **Untraced**: the display line says `libwaywallen_display 0.4.0`, while the vendored

## Harness notes (host, Plasma)

- `absmouse.py W H move:X,Y|click|rclick|key:ESC|wait:MS…` (scratch, not in the repo): a
  uinput device with ABS_X/ABS_Y 0..W-1/0..H-1 and BTN_LEFT/BTN_RIGHT is an absolute mouse
  to libinput (the VMware-mouse path), so KWin maps it to the screen 1:1 with no pointer
  acceleration; a second uinput device carries the keys. Needs `sudo` for `/dev/uinput`,
  1 s after `UI_DEV_CREATE` before the first event. wlr-virtual-pointer is not on KWin.
- Window geometry: KWin script, `w.clientGeometry` for `resourceClass == "org.zmural.Settings"`,
  sent with `callDBus` to a fake name and read with `dbus-monitor --session
  "interface='org.zmural.probe'"`; `grep -a` (the log gets NULs when truncated).
- Close the window: `w.closeWindow()` in a KWin script. Notifications: `dbus-monitor` on
  `org.freedesktop.Notifications.Notify`.
- Crash lines: `zig build crashcode -- "<line>"` in the release worktree finds
  `zig-out/package/debug/…/zmural.debug` by itself. `coredumpctl info <pid>` gives the same
  frames from the kept `.symtab`.
